# Harbor 0.5.0 — Update Harbor from Settings

Harbor 0.5.0 adds direct updates from Settings on Windows and Linux, alongside offline release highlights.

## What's changed

- **Download updates in Harbor:** when a new release is available, open **Settings → Releases & updates → Download update**. Follow progress, cancel a download or retry after a failure. Harbor verifies downloaded packages before marking them ready.
- **Install when you are ready:** choose **Install and restart** and confirm before Harbor closes active terminals, transfers and MCP connections. Downloads never install automatically on normal exit. Saved vault data and local MCP settings are preserved.
- **Keep the manual option:** **View releases & downloads** remains available. Current macOS builds continue to use manual installation.
- **Read what's new offline:** Settings includes release highlights and an optional **Show what’s new after updates** preference. Meaningful updates can announce their changes once after unlocking, when other dialogs are closed.
- **Complete update feeds:** the release includes Windows and Linux update metadata generated from the verified installer bytes, alongside `SHA256SUMS.txt` and `BUILDS.json`.

## Install or upgrade

**Users of Harbor 0.4.1 and earlier must install 0.5.0 manually once.** Download the package for Linux x64, Windows x64, macOS Intel or macOS Apple Silicon from this release, quit Harbor, install it and reopen the app. Confirm **0.5.0** in Settings. After this upgrade, supported Windows NSIS and Linux AppImage/DEB installations can download and install subsequent releases from Settings.

Automatic update checks remain optional and off by default. Downloads and installation only happen when requested. Linux DEB installation may ask for administrator authorization through the system permission agent. A writable AppImage location is needed for AppImage updates.

Keep the existing Harbor data directory. The application ID and vault format have not changed. Export an encrypted vault backup when a separate recovery copy is desired.

## Validation and known limitations

The release pipeline requires all four platform builds, source and packaged desktop workflow tests, and verification of all seven installers before publishing. Local checks also cover the real updater download/checksum pipeline with synthetic data, rejected corrupt downloads, cancellation/retry, restart confirmation, installation failure, and preservation of existing vault data.

End-to-end NSIS upgrades, AppImage replacement and elevated DEB upgrades still need representative installed-device checks. Automated tests do not certify real permission dialogs, password-manager approvals or suspend/resume behavior. See [validation and device checks](https://github.com/Jor-Tech/Harbor/blob/v0.5.0/docs/validation.md).

Installers are not publisher-signed. macOS builds are ad-hoc signed and not notarized, so direct macOS updates remain disabled. Gatekeeper and Windows SmartScreen may warn or block installation. Do not disable system-wide protections. Checksums verify downloaded bytes, not publisher identity; updates trust this repository's HTTPS release assets.
