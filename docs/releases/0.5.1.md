# Harbor 0.5.1 — MCP resume and authentication focus fixes

Harbor 0.5.1 fixes two connection workflow issues reported after 0.5.0.

## What's changed

- **Resume MCP access in an existing client:** locking the vault keeps established MCP client connections available. After unlocking and choosing **Resume MCP access**, the same client can submit new requests without restarting its app. Tool discovery and calls remain blocked until explicit resume. Locking still closes SSH sessions, cancels pending requests, clears temporary approvals and invalidates results in flight; reconnect to the SSH host before running further commands.
- **Type or paste verification codes immediately:** MFA/2FA and password prompts now focus their first input after the dialog opens. SSH key selection also receives focus. This applies to connections opened in Harbor and through MCP, including prompts opened from the system tray.

## Install or upgrade

On supported Windows NSIS and Linux AppImage/DEB installations of Harbor 0.5.0, open **Settings → Releases & updates → Check now**, then choose **Download update** and **Install and restart**. Harbor asks before closing active sessions. Automatic checks remain optional and off by default.

For macOS, Harbor 0.4.1 or earlier, or manual installation, download the package for your platform, quit Harbor, install it and reopen the app. Confirm **0.5.1** in Settings. Keep the existing Harbor data directory; the application ID, vault format and saved MCP permissions are unchanged. Export an encrypted vault backup when a separate recovery copy is desired.

## Validation and known limitations

Regression tests exercise repeated lock/unlock/resume using the same real MCP stdio bridge, blocked access before resume, invalidated SSH sessions and approvals, and client revocation. Desktop tests reconnect to SSH and execute a command through the same MCP client after resume. Authentication tests check focus and enter MFA codes without clicking the field, including MCP and system-tray flows.

The release pipeline requires all four platform builds, source and packaged desktop workflow tests, and verification of all seven installers before publishing. `SHA256SUMS.txt` and `BUILDS.json` identify the downloads and source commit.

The MCP fix has not been tested directly in ChatGPT. Disabling MCP, changing permissions, explicitly disconnecting or revoking a client, or quitting Harbor still closes the affected MCP connections. Interactive installer upgrades, real password-manager approvals and suspend/resume behavior still require representative device testing. See [validation and device checks](https://github.com/Jor-Tech/Harbor/blob/v0.5.1/docs/validation.md).

Installers are not publisher-signed. macOS builds are ad-hoc signed and not notarized, and macOS updates use manual installation. Gatekeeper and Windows SmartScreen may warn or block installation. Do not disable system-wide protections. Checksums verify downloaded bytes, not publisher identity.
