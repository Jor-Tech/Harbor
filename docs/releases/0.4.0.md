# Harbor 0.4.0 — Persistent sessions and command palette

Harbor 0.4.0 is the first release without an alpha suffix. It adds optional remote session persistence and a keyboard shortcut for navigating your SSH workspace.

## What's new

- **Persistent SSH sessions:** enable **Keep remote sessions running with tmux** in a host's settings. Each terminal and split pane gets its own remote session. Reconnect and saved workspaces reuse that session, so running commands can continue while Harbor is disconnected.
- **Reconnect after unlocking:** persistent tabs for saved hosts return after locking and unlocking the same vault in the running app. Choose **Reconnect** to authenticate again and resume. Unlocking does not reconnect automatically.
- **Command palette:** press **Ctrl+K** on Linux/Windows or **Cmd+K** on macOS to search hosts, open terminals, saved workspaces and actions. Navigate with the arrow keys, choose with Enter and close with Escape. Active dialogs and vault locking take precedence.
- **Clearer broadcast controls:** terminal target checkboxes are enabled only while **Broadcast input** is on.
- **Reliable backup identification:** backup management and retention preserve full 64-bit file IDs, avoiding rounded comparisons on Windows filesystems.

## Using persistent sessions

tmux must already be installed on the remote POSIX host. Harbor checks availability and reports an error if it is missing; it never installs tmux or replays previous commands. Normal SSH authentication, MFA, host-key checks and vault-lock protections still apply.

**Disconnect**, closing a tab and locking Harbor close the SSH connection while leaving the remote tmux session running. **End remote session** asks for confirmation and terminates that session and its processes. A remote reboot, a tmux shutdown or ending the session removes its state; reconnecting then starts an empty session.

Save a workspace to retain its remote-session references across app restarts. Lock/unlock tab restoration is limited to saved hosts in the same running app and does not restore the previous split layout. Local terminals and transient quick connections are not restored after lock. Remote tmux state belongs to the remote account and remains accessible there while Harbor is locked.

## Install or upgrade

Download the package for Linux x64, Windows x64, macOS Intel or macOS Apple Silicon from this release. Quit Harbor, install the new package and reopen it; confirm **0.4.0** in Settings. Keep a separate encrypted vault backup. Existing vault paths, application ID, vault format and MCP permissions are unchanged. Update checks remain optional; installation is manual.

The release pipeline checks all four platform builds and all seven installers before publishing. `SHA256SUMS.txt` and `BUILDS.json` identify the downloads and source commit.

## Known limitations

Installers are not publisher-signed. macOS builds are ad-hoc signed and not notarized; Gatekeeper and Windows SmartScreen may warn or block installation. Do not disable system-wide protections. Checksums verify file contents, not publisher identity.

CI uses temporary profiles and synthetic authentication. Interactive Windows/macOS installer upgrades, real password-manager approvals, suspend/resume and custom remote tmux configurations still require representative device testing; automated checks do not certify those scenarios. See [validation and device checks](../validation.md).
