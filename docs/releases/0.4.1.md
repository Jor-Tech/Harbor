# Harbor 0.4.1 — Desktop runtime update

Harbor 0.4.1 updates the desktop runtime and build tooling while preserving existing vaults, settings and SSH workflows.

## What's changed

- **Updated desktop runtime:** Electron moves from 44.9.1 to 45.2.3, including Chromium 156.0.8078.80 and Node.js 24.22.2. The runtime is included in the installer; desktop users do not need to install Node.js separately.
- **Consistent source builds:** local development and CI use Node.js 26.13.0 LTS, pinned in `.nvmrc`. Version-specific npm 12 install-script approvals keep native dependencies and packaging tools working after a clean installation.
- **Source export and documentation:** source exports include `.nvmrc`, and build instructions explain the separate desktop and development runtimes. Local MCP clients and experimental headless mode continue to support Node.js 24 or newer.

## Install or upgrade

Download the package for Linux x64, Windows x64, macOS Intel or macOS Apple Silicon from this release. Quit Harbor, install the new package and reopen it; confirm **0.4.1** in Settings. Keep a separate encrypted vault backup. Existing vault paths, application ID, vault format and MCP permissions are unchanged.

Use **Settings → Releases & updates → Check now** to find the update. Automatic checks remain optional and off by default; when enabled, Harbor checks shortly after launch and every twelve hours while running. Installation is manual.

The release pipeline checks all four platform builds and all seven installers before publishing. `SHA256SUMS.txt` and `BUILDS.json` identify the downloads and source commit.

## Known limitations

Installers are not publisher-signed. macOS builds are ad-hoc signed and not notarized; Gatekeeper and Windows SmartScreen may warn or block installation. Do not disable system-wide protections. Checksums verify file contents, not publisher identity.

Interactive Windows/macOS installer upgrades, real password-manager approvals, suspend/resume and custom remote tmux configurations still require representative device testing. Automated checks use temporary profiles and synthetic authentication and do not certify those scenarios. See [validation and device checks](https://github.com/Jor-Tech/Harbor/blob/v0.4.1/docs/validation.md).
